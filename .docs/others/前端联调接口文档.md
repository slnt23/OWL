## 2. 鉴权规则

### 2.1 登录与 Token

登录接口成功时，`Result.data` 返回 JWT 字符串。后续所有需要登录的接口请求头携带：

```text
Authorization: Bearer <token>
```

JWT 默认有效期 30 天，可通过 `jwt.expire-time` 配置调整。Token 中包含用户 ID、用户编码、邮箱、角色名和 token 版本。

### 2.2 角色说明

初始化角色见 `.docs/database/OWL/user/user_init_data.sql`：

| role_name | 说明 |
| --- | --- |
| `USER` | 普通用户，邮箱验证码登录自动注册时默认分配 |
| `MERCHANT` | 商家 |
| `ADMIN` | 系统管理员 |
| `CUSTOMER_SERVICE` | 客服 |

初始化账号：

| 用户名 | 密码 | 角色 |
| --- | --- | --- |
| `admin` | `admin123` | ADMIN |
| `merchant` | `merchant123` | MERCHANT |
| `user` | `user123` | USER |
| `service` | `service123` | CUSTOMER_SERVICE |

用户不能自行修改角色；角色变更只能由 `ADMIN` 通过后台用户管理接口完成。

### 2.3 路径权限

| 规则 | 路径 |
| --- | --- |
| 公开 | `/api/auth/send-code`、`/api/auth/login-email`、`/api/auth/login-password`、`/api/auth/password/reset` |
| 公开 | `/api/admin/feature/**`、`/api/admin/spotlight/**` |
| 公开 | `/api/public`、`/api/public/**`（当前无业务接口，预留） |
| 公开 | `/doc.html`、`/webjars/**`、`/swagger-ui/**`、`/v3/api-docs/**`、`/error`、`/favicon.ico` |
| 登录 | 除公开路径外的其他接口 |
| ADMIN | `/api/admin/**`，公开的 feature/spotlight 除外 |

未登录或 Token 无效时返回 HTTP 401；已登录但权限不足时返回 HTTP 403。除安全层拦截外，不存在的路径、页面和静态资源统一返回 404 JSON，不再返回 Whitelabel 页面。

## 3. 统一响应结构

所有业务接口返回 `Result<T>`：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

分页接口的 `data` 为 `ResultPage<T>`：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "currentPage": 1,
    "pageSize": 10,
    "total": 100,
    "totalPage": 10,
    "records": []
  }
}
```

前端统一以 `code` 判断成功失败，不依赖 `data` 是否为 null。部分接口的 `data` 会返回状态枚举字符串，例如 `SUCCESS`、`CREATED`。

## 4. 通用请求约束

### 4.1 密码规则

密码长度为 8-64 位，且必须同时包含字母和数字。适用于重置密码、修改密码、后台新增用户、后台重置密码。

### 4.2 验证码规则

| 项 | 值 |
| --- | --- |
| 验证码格式 | 6 位数字 |
| 有效时间 | 5 分钟 |
| 发送冷却 | 同邮箱 5 分钟内不可重复发送 |
| 错误次数 | 最多 5 次，超过后需重新发送 |

### 4.3 分页规则

分页参数名称通常是 `pageNum`、`pageSize`，部分接口放在 query，部分放在 JSON body。

商品/购物车/订单分页接口：

- `pageSize` 超过 50 会被后端限制为 50。

后台用户分页接口：

- `pageSize` 超过 100 会被后端限制为 100。

### 5.2 登录说明

- `send-code`：发送验证码到邮箱。
- `login-email`：使用邮箱验证码登录；邮箱未注册时自动创建账号，默认角色为 `USER`。
- `login-password`：使用邮箱和密码登录；未设置密码的账号会返回 `401004`。
- `password/reset`：通过邮箱验证码重置密码，重置后该用户旧 Token 全部失效。
- `logout`：将当前 Token 加入黑名单。

### 5.5 示例

发送验证码：

```bash
curl -X POST http://127.0.0.1:18080/api/auth/send-code \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com"}'
```

邮箱验证码登录：

```bash
curl -X POST http://127.0.0.1:18080/api/auth/login-email \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","code":"123456"}'
```


## 11. 联调注意与已知问题

- 未登录访问受保护未知路径时，安全层会先返回 401；已登录访问未知路径返回 404 JSON。
- 焦点项目更新接口 `PUT /api/admin/spotlight/{id}` 当前用 JSON body 接收含文件字段的 DTO，无法直接上传文件，需要后端调整。
- 焦点项目更新时路径 `id` 不会自动写入 DTO，请求体必须额外传 `id`。
- 购物车新增、更新、删除使用请求传入的用户 ID，购物车列表使用登录态用户 ID，前后端需要保持一致。
- 消费者、商家商品与订单接口只要求登录，不强制 `MERCHANT` 角色；后台管理接口 `/api/admin/**` 才要求 `ADMIN`。
- 商家商品 `ProductDTO.id` 标注了 `@NotEmpty`，新增商品时是否传值需与后端确认。
- 部分订单/商品列表接口的 `pageNum`、`pageSize` 没有标注 `@RequestParam`，虽然当前可选，联调时建议始终传值。
- 商品列表的 `productName` 必填，查询全量时传空字符串。
- 流式聊天返回 SSE，前端必须使用事件流解析。
- 时间字段使用 ISO 格式，例如 `2026-06-05T10:30:00`。
- 价格中心空实现接口不要接入正式页面流程。
