# OWL 文档中心

本文档是 OWL 仓库的文档入口。所有写入 `.docs` 的文档都应遵守[《OWL 文档编写规范》](spec/documentation-standard.md)。

## 文档地图

| 路径                        | 内容                                                                                                                                           | 负责人         |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| [文档中心](README.md)       | 文档地图、职责边界、生命周期                                                                                                                   | 仓库 Owner     |
| [仓库 README](../README.md) | 项目总览、技术栈、快速启动                                                                                                                     | 仓库 Owner     |
| [ADR 目录](adr/)            | 架构决策记录，文件名为 `ADR-XXX-中文标题.md`                                                                                                   | 对应模块 Owner |
| [开发计划目录](plans/)      | 模块开发计划与实施步骤                                                                                                                         | 对应模块 Owner |
| [数据库目录](database/)     | DDL、表结构说明、示例数据                                                                                                                      | 数据库 Owner   |
| [规范目录](spec/)           | 公共模块架构、代码设计方案、代码注释规范、文档编写规范、数据库命名规范、默认保底规范，含[公共模块架构说明](spec/common-module-architecture.md) | 仓库 Owner     |
| [开发手册目录](guides/)     | 新模块开发指南等操作手册                                                                                                                       | 仓库 Owner     |
| [DevOps 目录](devops/)      | CI/CD、GitHub 工作流等运维文档                                                                                                                 | 仓库 Owner     |
| [素材目录](assets/)         | 图片等静态素材                                                                                                                                 | 仓库 Owner     |

## 文档职责

| 文档类型    | 回答的问题                                             | 维护要求                             |
| ----------- | ------------------------------------------------------ | ------------------------------------ |
| 仓库 README | 这是什么项目、如何快速跑起来                           | 技术栈或启动方式变化时同步更新       |
| ADR         | 为什么做这个架构决策、放弃了哪些方案                   | 决策变化时新增或废弃记录，不重写历史 |
| 开发计划    | 模块分几步落地、每步做什么                             | 阶段完成时更新进度，方案变更时同步   |
| 设计规范    | 代码怎么设计、注释怎么写、文档怎么写、数据库表怎么命名 | 规则变化时先评审再发布               |
| 开发手册    | 新模块怎么加、环境怎么搭                               | 步骤或规范变化时同步更新             |
| DevOps      | CI/CD 怎么配、怎么部署                                 | 流水线或部署方式变化时同步更新       |

## 生命周期速查

正式文档按 `草稿 -> 评审中 -> 已批准 -> 已废弃` 演进；状态和负责人写在文档头部。任何文档变更都通过 PR 评审，不允许绕过评审直接合入。

## 红线

- 禁止在文档中提交密码、Token、私钥、真实个人信息。
- 禁止把聊天记录或问答原文直接粘贴为正式文档。
- 禁止复制粘贴代码或表结构作为唯一事实来源，应链接到源码。
- 禁止让文档长期停留在“已过时但未标记”的状态。
